# 转速估计方案

## 1. 输入条件

AS5600 提供 12 位单圈机械角度，范围约为 `0~6283mrad`。TIM2 调度基准频率为 `4000Hz`，默认 `sensor_hz = 2000Hz`，因此传感器任务每 2 个调度节拍执行一次，每 `0.5ms` 读取一次角度。

由于传感器角度在一圈后回到零点，速度估计必须处理跨零；同时，单个角度计数约为 `1.534mrad`，直接差分会放大量化噪声。

## 2. 方案一：相邻采样直接差分

计算方式：

```text
delta = unwrap(current_angle - previous_angle)
speed = delta / sample_time
```

优点：

- 延迟最低。
- 相邻采样转角小于半圈时，可以正确处理跨零和方向。
- 实现简单，占用内存少。

缺点：

- AS5600 的单个计数量化误差会被 `0.5ms` 采样间隔放大。
- 静止或低速时，估计值容易在多个离散速度之间跳动。
- 不适合直接作为高增益速度环反馈。

## 3. 方案二：单圈角度窗口端点差分

计算方式：

```text
delta = unwrap(current_single_turn_angle - old_single_turn_angle)
speed = delta / window_time
```

这是旧实现使用的方式，窗口为 20 个采样点，默认窗口时间约为 `10ms`。

优点：

- 窗口平均能够明显降低量化噪声。
- 计算量和内存占用较小。

缺点：

- 只能确定窗口内不超过半圈的运动方向。
- 窗口累计转角超过 `π` 后，会把正向大角度误判为反向小角度，产生速度方向翻转。
- 约 `10ms` 的测量延迟对 `500Hz` 速度环偏大。

## 4. 方案三：连续角度解包后窗口差分

计算分为两步。

第一步对每个相邻采样执行跨零处理，并累计连续角度：

```text
sample_delta = unwrap(current_angle - previous_angle)
continuous_position += sample_delta
```

第二步使用连续角度的窗口变化计算平均速度：

```text
speed = (current_continuous_position - old_continuous_position) / window_time
```

优点：

- 相邻采样间转角小于半圈时，可连续记录任意圈数。
- 不会因整个测速窗口转过半圈而发生方向翻转。
- 窗口平均保留了抑制 AS5600 量化噪声的能力。
- 使用实际时间差，可容忍调度周期的小幅抖动。

缺点：

- 比方案一和方案二多维护连续角度及环形历史。
- 如果相邻两次采样之间已经转过半圈，仍然存在方向歧义。
- 窗口越长，噪声越小，但反馈延迟越大。

## 5. 当前选择

当前固件采用方案三：

| 项目 | 配置 |
| --- | --- |
| 传感器采样频率 | 默认 `2000Hz` |
| 速度环频率 | `500Hz` |
| 连续角度窗口 | 10 个采样点 |
| 名义测速窗口 | 约 `5ms` |
| 速度单位 | `mrad/s` |

10 点窗口在延迟和噪声之间取折中。相邻采样只用于角度解包，最终反馈速度仍由窗口平均得到，并非直接使用单次差分值。

## 6. AS5600 采样链路

当前固件使用 STM32F103 的 I2C1 硬件外设读取 AS5600，接口为 `PB6/SCL` 和 `PB7/SDA`，总线频率为 `400kHz`。每次采样执行以下完整事务：

```text
START + 从机写地址 + RAW_ANGLE_H(0x0C)
RESTART + 从机读地址 + 角度高字节 + 角度低字节 + STOP
```

实测一次完整角度读取耗时约为 `118~119us`，约占默认 `0.5ms` 采样周期的 `24%`，完成读取后还剩约 `381us` 的周期余量。读取耗时只表示 MCU 发起 I2C 事务到收到两个角度字节的时间，不包含 AS5600 芯片内部滤波产生的数据延迟。

固件初始化时将 AS5600 的完整 CONF 写为 `0x0700`，并要求读回值一致。CONF 高、低字节分别使用独立的单字节 I2C 事务，避免当前器件连续读取 CONF 时低字节异常返回 `0xFF`：

| 配置位 | 数值 | 作用 |
| --- | --- | --- |
| `PM` | `00` | 连续工作模式，避免低功耗轮询降低角度刷新率 |
| `HYST` | `00` | 不增加角度迟滞 |
| `OUTS` | `00` | 默认模拟输出，I2C 角度读取不依赖该输出 |
| `PWMF` | `00` | 默认 PWM 频率，I2C 角度读取不依赖该配置 |
| `SF` | `11` | 2 倍慢滤波，稳定时间典型值约 `0.286ms` |
| `FTH` | `001` | 输入变化超过 6 LSB 时进入快速滤波 |
| `WD` | `0` | 禁用静止一分钟后自动进入 LPM3 |

AS5600 内部采样周期典型值为 `150us`，约为 `6.67kHz`。在 `PM=00` 下，默认 `2000Hz` 的 MCU 读取周期为 `500us`，因此能够在相邻两次读取之间获得新的传感器采样。若 CONF 写入或读回不是 `0x0700`，固件停止初始化，不允许 FOC 使用不确定的角度刷新率。

AS5600 数据手册允许把内部地址指针保持在 `RAW_ANGLE_H`，后续采样只接收两个数据字节。该方式理论上可将总线事务缩短到约 `71us`，但当前实物测试时原始角度会在 `784` 和 `1962` 两个错误值之间交替，进而产生约 `±235000~294500mrad/s` 的错误速度。因此当前版本每次采样都重新发送 `RAW_ANGLE_H`，不启用固定地址指针优化。

STM32F1 的 I2C 接收外设存在严格的 EV6_3 软件时序要求。读取一个字节时，固件在同一中断临界区内完成 `清除 ADDR + 产生 STOP`；读取两个字节时，固件依次执行以下步骤：

```text
设置 POS
关闭中断 -> 清除 ADDR -> 清除 ACK -> 恢复中断
等待 BTF
关闭中断 -> 产生 STOP -> 读取第一个 DR -> 恢复中断
读取第二个 DR
```

临界区只覆盖几条寄存器操作，不覆盖完整 I2C 事务。该处理防止 4kHz 定时器或 CAN 中断插入接收关键窗口，避免 DR 与移位寄存器错位后交替返回历史角度。修复前高速 trace 的 `sensor_angle` 只在 `1569mrad` 和 `1962mrad` 之间跳变；该现象不是 AS5600 的 12 位量化颗粒，而是 STM32F1 接收时序错误。

高速 trace 中的 `sensor_angle` 已经由 AS5600 原始 `0~4095` count 转换为 `0~6283mrad`，因此不能把 trace 中的数值直接当作 12 位原始 count。EV6_3 修复后，静止状态的 512 点 trace 在 `4710~4725mrad` 的邻近区间内变化，不再出现两个历史角度交替。随后执行 `q_target=1000`、持续约 `300ms` 的限时测试，机械角度从约 `3528mrad` 连续变化到 `2582mrad`，峰值速度约为 `-6800mrad/s`，证明角度读取和 FOC 换相已经恢复连续。

默认采样链路的时间关系为：

| 项目 | 当前值 |
| --- | --- |
| TIM2 调度周期 | `0.25ms`，即 `4000Hz` |
| AS5600 采样周期 | `0.5ms`，即 `2000Hz` |
| AS5600 内部采样周期 | 典型 `0.15ms`，约 `6.67kHz` |
| 单次硬件 I2C 读取 | 实测约 `118~119us` |
| AS5600 慢滤波设置 | `SF = 11`，典型约 `0.286ms` |
| 速度估计窗口 | 10 点，名义约 `5ms` |
| 速度环执行周期 | `2ms`，即 `500Hz` |

`sensor_hz` 可以通过 CAN FOC 基础配置修改，当前允许范围为 `1~4000Hz`。提高采样频率会缩短相邻角度解包的时间间隔，但也会减少 I2C 读取后的调度余量；修改后应同时检查实际采样执行情况和速度估计窗口时间。

## 7. 调参注意事项

- 修改测速窗口后，应重新整定速度环 PID。
- 首次调试应限制 `OUT_MAX`，避免方向或参数错误导致高速输出。
- 如果低速噪声仍然明显，可适当增加窗口，或在窗口速度后增加一阶低通滤波。
- 如果动态响应偏慢，应优先检查实际传感器采样率和主循环执行周期，再决定是否缩短窗口。
