# CAN 协议说明

## 1. 概述

本项目使用标准帧 `CAN 2.0A`，数据长度固定按 8 字节处理。多字节整数统一使用小端格式。除电机主动上报帧外，普通命令和应答帧均使用 Byte0 作为命令码。

每台电机出厂或擦除参数后处于未配置状态：

- 管理节点 ID：`0x7E`
- 管理命令 ID：`0x17E`
- 管理应答 ID：`0x1FE`
- 管理上报 ID：`0x27E`
- 未配置电机以 2Hz 频率上报 `UID32`
- 未配置电机不响应普通控制命令，不主动上报电机状态，也不允许 OTA
- 配置业务 CAN ID 后进入运行状态，并使用业务节点 ID 响应控制命令

`UID32` 是由 STM32F103 96 位 UID 派生出的 32 位短 UID，用于在管理 ID 下区分同总线上的多台电机。

## 2. ID 规划

标准帧 ID 由基础 ID 与节点 ID 相加得到：

| 类型 | 标准帧 ID |
| --- | --- |
| 主机命令 | `0x100 + node_id` |
| 电机应答 | `0x180 + node_id` |
| 电机上报 | `0x200 + node_id` |
| OTA 控制 | `0x400 + node_id` |
| OTA 响应 | `0x500 + node_id` |

管理节点固定使用 `node_id = 0x7E`。

## 3. 通用帧格式

| 字节 | 含义 |
| --- | --- |
| Byte0 | 命令码 |
| Byte1~Byte7 | 命令参数 |

应答帧格式：

| 字节 | 含义 |
| --- | --- |
| Byte0 | 回显命令码 |
| Byte1 | 状态码 |
| Byte2~Byte7 | 附加返回数据 |

状态码：

| 状态码 | 含义 |
| --- | --- |
| `0x00` | 成功 |
| `0x01` | 命令非法 |
| `0x02` | 参数非法 |
| `0x03` | 模式非法 |
| `0x04` | CAN 错误 |

## 4. 管理命令

### 4.1 未配置发现上报

- 命令码：`0x60`
- 方向：电机 -> 主机
- 帧 ID：`0x27E`
- 频率：2Hz，仅未配置状态上报

| 字节 | 含义 |
| --- | --- |
| Byte0 | `0x60` |
| Byte1 | 配置状态，`0 = 未配置`，`1 = 已配置` |
| Byte2 | 当前节点 ID，未配置时为 `0x7E` |
| Byte3~Byte6 | `UID32`，小端 |
| Byte7 | 保留 |

### 4.2 识别灯效

- 命令码：`0x61`
- 方向：主机 -> 电机
- 帧 ID：`0x17E`

| 字节 | 含义 |
| --- | --- |
| Byte0 | `0x61` |
| Byte1 | 闪烁频率，单位：Hz，固件限制到 1~20Hz |
| Byte2 | 持续时间，单位：秒，0 表示默认 5 秒，最大 60 秒 |
| Byte3~Byte6 | 目标 `UID32`，小端 |
| Byte7 | 保留 |

匹配 `UID32` 的电机会进入识别灯效，并通过 `0x1FE` 应答：

| 字节 | 含义 |
| --- | --- |
| Byte0 | `0x61` |
| Byte1 | 状态码 |
| Byte2 | 实际闪烁频率，单位：Hz |
| Byte3 | 实际持续时间，单位：秒 |
| Byte4~Byte7 | `UID32`，小端 |

### 4.3 配置业务 CAN ID

- 命令码：`0x62`
- 方向：主机 -> 电机
- 帧 ID：`0x17E`

| 字节 | 含义 |
| --- | --- |
| Byte0 | `0x62` |
| Byte1 | 新业务节点 ID，范围 `0x01~0x7F`，不能为 `0x7E` |
| Byte2 | 保留 |
| Byte3~Byte6 | 目标 `UID32`，小端 |
| Byte7 | 保留 |

匹配 `UID32` 且参数合法后，固件会保存 `can_id` 与 `can_configured = 1`，切换到运行状态，并重新配置 CAN 过滤器。

应答帧 ID 为 `0x1FE`：

| 字节 | 含义 |
| --- | --- |
| Byte0 | `0x62` |
| Byte1 | 状态码 |
| Byte2 | 新业务节点 ID |
| Byte3~Byte6 | `UID32`，小端 |
| Byte7 | 保留 |

## 6. PID 命令

PID 参数编号：

| 编号 | 含义 |
| --- | --- |
| `0x00` | `P` |
| `0x01` | `I` |
| `0x02` | `D` |
| `0x03` | `I_ACC_MAX` |

| `0x12` | 主机 -> 电机 | 设置位置环参数 |
| `0x13` | 主机 -> 电机 | 读取位置环参数 |

| 字节 | 含义 |

FOC 基础配置参数编号：

| 编号 | 参数 | 单位 | 默认值 | 数值范围 |
| --- | --- | --- | --- | --- |
| `0x00` | `pole_pairs` | 个 | `7` | `1~32` |
| `0x01` | `master_voltage_mv` | 毫伏 | `12000` | `1~60000` |
| `0x02` | `control_hz` | Hz | `2000` | `1~4000` |
| `0x03` | `sensor_hz` | Hz | `2000` | `1~4000` |
| `0x04` | `phase_map` | 无 | `0` | `0~1` |
| `0x05` | `as5600_boot_conf` | 无 | 只读 | 启动时 CONF 原始值 |
| `0x06` | `as5600_active_conf` | 无 | 只读 | 当前 CONF 原始值 |
| `0x07` | `as5600_read_last_us` | us | 只读 | 最近一次 RAW ANGLE 读取耗时 |
| `0x08` | `as5600_read_min_us` | us | 只读 | 最小 RAW ANGLE 读取耗时 |
| `0x09` | `as5600_read_max_us` | us | 只读 | 最大 RAW ANGLE 读取耗时 |
| `0x0A` | `as5600_read_average_us` | us | 只读 | 平均 RAW ANGLE 读取耗时 |

固件只校验数值合法范围，不判断这些参数是否符合实际电机和电气系统。配置保存到用户信息页尾部扩展区，`0x25` 只复位 CAN ID 和 CAN 配置状态，不复位 FOC 基础配置。

固件启动时保存 AS5600 原始 CONF，然后将完整 CONF 写为 `0x0700` 并执行读回校验。CONF 高、低字节分别使用独立的单字节 I2C 事务，避免当前器件连续读取 CONF 时低字节异常返回 `0xFF`。该配置对应 `PM=00` 连续工作模式、`HYST=00`、`OUTS=00`、`PWMF=00`、`SF=11`、`FTH=001` 和 `WD=0`。AS5600 内部采样周期典型值为 `150us`；慢滤波稳定时间约为 `0.286ms`，输入变化超过 6 LSB 时启用快速滤波。若读回值不是 `0x0700`，AS5600 初始化失败，FOC 不启动。

AS5600 使用 I2C1 硬件外设，以 400 kHz 运行。控制循环每次采样均发送 `RAW_ANGLE_H` 寄存器地址，再连续接收两个角度字节。读取耗时使用 Cortex-M3 DWT 周期计数器测量，包含寄存器地址和两字节数据的完整硬件 I2C 事务。

STM32F1 单字节和双字节 I2C 接收按照 EV6_3 时序执行，在 `清除 ADDR/配置 ACK` 以及 `产生 STOP/读取首字节` 的关键窗口临时关闭中断，防止定时器或 CAN 中断造成 DR 与移位寄存器错位。临界区不覆盖完整 I2C 事务。

AS5600 数据手册允许把内部地址指针保持在角度高字节，后续只执行两字节接收。但当前实物在这种读取方式下会让原始角度在两个错误值之间交替，因此固件不启用该优化。实测每次重新发送寄存器地址时角度数据稳定，读取耗时约为 `118us`，仍显著低于原软件 I2C 的约 `343us`。

`phase_map` 用于配置 FOC 逻辑三相 `A/B/C` 到 TIM1 物理输出 `CH1/CH2/CH3` 的连接顺序：

| `phase_map` | TIM1 CH1 | TIM1 CH2 | TIM1 CH3 |
| --- | --- | --- | --- |
| `0` | A | B | C |
| `1` | A | C | B |

固件只保留正序和反序两个选项。`phase_map=0` 为正序，`phase_map=1` 交换 B/C 两相形成反序；写入其它编号会返回参数错误。

## 8. 电机主动上报

电机主动上报默认关闭，默认周期为 `10ms`。已配置电机只有在 `0x23` 打开主动上报后，才会按配置周期上报位置和速度。该上报帧不带命令码，位置和速度在同一帧内同时上报：

| 字节 | 含义 |
| --- | --- |
| Byte0~Byte3 | 当前位置，`int32`，单位：mrad |
| Byte4~Byte7 | 当前速度，`int32`，单位：mrad/s |

未配置电机只发送管理发现上报，不发送位置和速度上报。

### 8.1 速度环 PID 临时诊断上报

开启电机主动上报后，固件每 `3ms` 发送一帧速度环 PID 诊断帧，约 `12ms` 完成一组。四帧来自同一次运行时快照，诊断功能用于临时调试，所有浮点数均为 IEEE 754 小端 `float32`。

| CAN ID | Byte0~Byte3 | Byte4~Byte7 |
| --- | --- | --- |
| `0x300 + node_id` | 目标速度 | 反馈速度 |
| `0x320 + node_id` | 当前误差 | 误差变化量 |
| `0x340 + node_id` | 积分累计值 | 积分输出值 |
| `0x360 + node_id` | PID 最终输出 | 实际 q 轴目标，`int32` |

诊断帧与位置速度主动上报同时启停，但单帧周期固定为 `3ms`，不跟随位置速度上报周期变化。诊断帧分时发送，避免连续四帧占满 bxCAN 的三个发送邮箱。

### 8.2 FOC 高速环形记录

命令 `0x41` 控制固件 RAM 中的 FOC 高速环形记录，Byte1 为操作编号：`0` 表示开始，`1` 表示停止并冻结，`2` 表示上传。应答负载依次包含操作编号、记录状态、采样数量 `uint16` 和配置采样频率 `uint16`。

高速记录在传感器更新后采样，不在实时控制过程中发送 CAN。缓存容量为 512 点，检测到 `|speed| >= 10000mrad/s` 后再记录 384 点并自动冻结，最终窗口约包含 128 点触发前数据和 384 点触发后数据。每点包含系统时间戳、原始角度、机械角度、电角度、速度、q 轴目标和三相 PWM 占空比。

机械角度和电角度统一采用 `zero_angle - sensor_angle` 的正方向。该坐标约定要求使用反序三相映射；默认接线下设置 `phase_map=1` 交换 B/C 两相，并在修改相序后重新执行零点校准。

上传时每个采样拆分为三个标准帧，Byte0~Byte1 为采样序号，Byte2~Byte7 为连续 6 字节采样数据：

| CAN ID | 数据分片 |
| --- | --- |
| `0x380 + node_id` | 字节 0~5 |
| `0x3A0 + node_id` | 字节 6~11 |
| `0x3C0 + node_id` | 字节 12~17 |

上报周期由 FOC 调度周期检查并节流，当前 FOC 调度基准为 `4000Hz`。因此配置为 `2ms` 时，理论上可达到约 `500Hz` 上报频率。

## 9. 灯效区分

| 固件状态 | 灯效 |
| --- | --- |
| App 未配置 | 2 秒周期短闪一次 |
| App 已配置运行 | 2 秒周期三连短闪 |
| App 识别 | 按上位机指定频率闪烁 |
| Boot 待机 | 1Hz 闪烁 |
| Boot 升级中 | 5Hz 快闪 |

## 10. 过滤器说明

App CAN 初始化后接收：

```text
0x17E
0x100 + node_id
0x400 + node_id
```

未配置时 `node_id = 0x7E`，普通控制命令和 OTA 启动帧都会被协议层忽略，只处理发现、识别和配置业务 CAN ID 等管理命令。

## 11. OTA 准入规则

OTA 只允许在电机已经配置唯一业务 CAN ID 后执行。上位机需要使用目标业务节点 ID 计算 OTA 帧 ID：

```text
OTA 控制 = 0x400 + node_id
OTA 响应 = 0x500 + node_id
```

多台未配置电机同时位于总线时，必须先通过 `0x27E` 收集 `UID32`，再通过 `0x61` 识别目标，最后通过 `0x62 + UID32` 配置唯一业务节点 ID。禁止直接对未配置管理节点 `0x7E` 发起 OTA，避免多台电机同时进入 Boot 并争用 `0x57E` 响应帧。

## 12. Flash 存储布局

64KB Flash 当前划分如下：

| 区域 | 起始地址 | 结束地址 | 大小 | 说明 |
| --- | --- | --- | --- | --- |
| Boot | `0x08000000` | `0x08004400` | 17KB | Bootloader 固件 |
| App | `0x08004400` | `0x0800F800` | 45KB | App 固件 |
| OTA 信息页 | `0x0800F800` | `0x0800FC00` | 1KB | OTA 标志、App 长度、App CRC16 |
| 用户信息页 | `0x0800FC00` | `0x08010000` | 1KB | CAN ID、零点、上报配置、FOC 基础配置 |

OTA 信息页独立于用户信息页。OTA 成功后 Boot 只更新 OTA 信息页，不擦写用户信息页；App 请求进入 Boot OTA 时也只更新 OTA 信息页的 OTA 标志。

## 13. OTA 业务头与校验

OTA 使用 YMODEM 传输，YMODEM 文件内容由 `128` 字节业务头和 App 镜像组成。Boot 不会把业务头写入 App Flash，App Flash 起始地址仍然写入真实 App 镜像。

业务头字段均使用小端格式：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| `0x00` | 16 | 魔数，固定为 `MOTOR_DUCK_OTA\0\0` |
| `0x10` | 1 | 业务头版本，当前为 `1` |
| `0x11` | 1 | 业务头长度，当前为 `128` 字节 |
| `0x12` | 2 | 业务头 CRC16-CCITT，计算时本字段按 `0` 处理 |
| `0x14` | 4 | App 镜像长度，单位：字节 |
| `0x18` | 2 | App 镜像 CRC16-CCITT |
| `0x1A` | 102 | 保留，当前填 `0` |

CRC16-CCITT 使用多项式 `0x1021`，初值 `0x0000`。Boot 在收到首个数据包后校验业务头，业务头非法时不会擦除 App 区；写入完成后会读取 App Flash 重新计算 App CRC16，和业务头中的 App CRC16 不一致则 OTA 失败。

OTA 成功后，Boot 会把 `App 镜像长度` 和 `App CRC16` 保存到 OTA 信息页，并将 OTA 标志切回允许跳转 App。Boot 每次启动跳转 App 前都会先检查向量表合法性，再根据 OTA 信息页记录重新计算完整 App CRC16；校验失败会停留在 Boot。
